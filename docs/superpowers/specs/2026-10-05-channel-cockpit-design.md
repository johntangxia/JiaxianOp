# 频道运营驾驶舱 · 设计方案

- 日期：2026-10-05
- 状态：已实现（实施计划见 [频道运营驾驶舱](../plans/2026-10-05-channel-cockpit.md)）
- 前置依赖：[数据基础](2026-10-05-data-foundation-design.md)（28 个频道、加入社区日期）和 [行为数据扩充](2026-10-05-behavior-data-design.md)（来源、入口频道、曝光、停留）已实现。

## 1. 背景与目标

运营想回答两件事：**各频道的流量从哪来、各入口分发得好不好**，以及**哪个频道哪里有问题**。头条式的频道体系里，综合频道（关注、推荐、热点、视频、直播）和领域频道（23 个）都有自己的入口和信息流，领域频道自己在入口做的分发（"自主分发"）是重要指标，要单列出来，和综合频道的分发并排看。

本计划交付：一个频道运营驾驶舱页面（总览 + 单频道详情），综合频道和领域频道用同一套分析口径，自动诊断指出每个频道的问题。

## 2. 口径：两类频道共用一套"分发"指标

任何频道（综合或领域）都有"自己入口的分发"，指标相同，来自曝光表（`impression.entry_channel_id = 该频道`）：

| 指标 | 含义 |
|---|---|
| 曝光 | 该频道入口展示内容的次数 |
| 点击 | 入口来源的浏览数（`pv_log.source_type = 'ENTRY'` 且入口是该频道） |
| 点击率 CTR | 点击 / 曝光 |
| 触达 UV / 点击 UV | 看到过内容的去重员工数 / 点击过内容的去重员工数 |
| 平均停留 | 入口来源浏览的平均停留秒数 |

**领域频道还有"内容侧"指标**（内容属于该领域，不论从哪里被看到）：

| 指标 | 含义 |
|---|---|
| PV / UV | 该领域内容的浏览数 / 去重浏览员工数 |
| 来源构成 | 自主入口、综合入口、搜索、分享、其他的 PV |
| **自主分发占比** | 自主入口 PV / PV（单列展示） |
| 综合依赖度 | 综合入口 PV / PV |
| 互动数、互动率 | 点赞、转发、收藏、评论数（期间内发生）；互动率 = 互动数 / PV |
| 头部集中度 | 单篇最高 PV 占比、前三篇占比 |
| 供给 | 期间发布内容数、去重作者数 |

**综合频道**没有自己的内容，所以没有内容侧指标，改看"内容覆盖"：入口点击涉及多少个领域、点击最多的领域占比。

每个指标同时给出**上一个等长周期**的值，用来看环比。

## 3. 自动诊断与基准

- **基准**：同类频道的中位数（领域频道之间比，综合频道之间比），只统计期间有数据的频道。
- **诊断规则**（阈值是经验值，常量集中在 `ChannelDiagnoser`）：

| 代码 | 适用 | 触发条件（且数据量足够） | 级别 |
|---|---|---|---|
| NO_OWN_ENTRY_TRAFFIC | 领域 | PV ≥ 30 且自主入口点击为 0 | 严重 |
| LOW_OWN_ENTRY_SHARE | 领域 | 自主分发占比 < 中位数 × 0.5 | 警告 |
| HIGH_COMPOSITE_DEPENDENCY | 领域 | 综合依赖度 > 中位数 × 1.5 | 警告 |
| LOW_OWN_CTR | 领域 | 自主入口曝光 ≥ 50 且 CTR < 中位数 × 0.7 | 警告 |
| LOW_INTERACTION | 领域 | PV ≥ 30 且互动率 < 中位数 × 0.6 | 警告 |
| HIGH_CONCENTRATION | 领域 | PV ≥ 30 且单篇占比 > 40% | 提示 |
| LOW_SUPPLY | 领域 | 中位数发布数 ≥ 2 且本频道发布数 < 中位数 × 0.5 | 警告 |
| PV_DROP | 领域 | 上期 PV ≥ 30 且本期 < 上期 × 0.8（< 0.5 为严重） | 警告/严重 |
| LOW_CTR | 综合 | 曝光 ≥ 50 且 CTR < 综合中位数 × 0.7 | 警告 |
| CLICK_DROP | 综合 | 上期点击 ≥ 30 且本期 < 上期 × 0.8（< 0.5 为严重） | 警告/严重 |
| LOW_COVERAGE | 综合 | 点击 ≥ 30 且覆盖领域数 < 有内容领域数的一半 | 提示 |

每条诊断带一句人话说明（含具体数字和基准）。

## 4. 接口

- `GET /api/channels/cockpit?from=&to=`：返回综合频道行和领域频道行（每行含当期、上期、诊断）、两类基准中位数、上一周期的起止日期。`from`、`to` 必填，`to ≥ from`，区间不超过 366 天；否则 400 + 一句文字说明。
- `GET /api/channels/{id}/detail?from=&to=&granularity=`：返回该频道的行（含诊断）、趋势（粒度 DAY/WEEK/MONTH，默认 DAY；领域频道是按来源堆叠的 PV + 自主入口曝光/点击/CTR，综合频道是曝光/点击/CTR）、构成（领域频道是来源占比，综合频道是点击内容所属领域占比，取前 8 + 其他）、Top 10 内容（内容编号、类型、账号、发布时间、PV、互动数）。频道不存在 404。
- 旧数据（来源为空）的浏览记入"其他"。

## 5. 页面

- **频道驾驶舱**（`/channels`）：日期范围（默认 PV 数据最后一天往前 30 天）。顶部并排两组 KPI：**综合频道入口分发**（总曝光、点击、CTR）和**领域频道自主入口分发**（同样三项）；中间是领域频道整体的来源构成。下面是两张表：综合频道表（分发指标 + 覆盖领域数 + 诊断），领域频道表（**自主分发**列突出：自主曝光、自主点击、自主 CTR、自主分发占比，加综合依赖度、PV、UV、互动率、发帖数、作者数、头部集中度、诊断），支持按列排序，环比用涨跌色标出；点击一行进入详情。
- **频道详情**（`/channels/:id`）：KPI 卡片（当期 vs 上期）、诊断列表、趋势图（DAY/WEEK/MONTH 切换）、构成饼图、Top 内容表。
- 侧边栏新增"频道驾驶舱"。

## 5.1 实现时的偏差

- 表格拆成 `CompositeTable`、`DomainTable`，另有 `DistributionCompare`（顶部三块并排：综合入口分发、领域自主入口分发、领域内容来源构成饼图）、`DiagnosisTags`、`DeltaText`，没有单独的 `ChannelTable`。
- **默认区间改为近半年**（原设计是近 30 天），日期选择器带"近 30 天/90 天/半年/一年"快捷项：演示库只有 300 篇内容、23 个领域，30 天内多数领域频道没有足够数据量，诊断规则（PV ≥ 30、曝光 ≥ 50）不会下结论。详情页区间超过 45 天时默认按周看。
- 详情页的"互动数"在综合频道的 Top 内容里是该入口点击的内容在期间内收到的互动，不是入口带来的互动。
- `@Repository` 会把 `IllegalArgumentException` 包成别的异常，所以 Top 内容的 `limit` 不在仓库里校验（它是服务里的内部常量）。
- 冒烟测试新增 5 项驾驶舱检查（结构、PV 合计、详情、颠倒日期 400、不存在频道 404）。
- 已知局限：诊断阈值是经验值，且基准是同类频道中位数，频道很少或数据很薄时会出现"全体都低于基准"的情况；综合频道的"覆盖领域"只统计有点击的领域。

## 6. 测试

- 纯函数：`ChannelDiagnoser`（每条规则的触发和不触发、数据量不足时不触发）、中位数、占比计算。
- 集成：`ChannelQueryRepositoryIT`（2019 年夹具：来源分类、自主 vs 综合入口、曝光/点击/UV、互动、供给、集中度、覆盖）、`ChannelCockpitControllerIT`（参数校验、404、正常返回结构）、`ChannelCockpitEndToEndIT`（回填后分发点击 = 入口来源 PV、两类频道行数 5 和 23）。
- 前端：指标格式化与环比、图表配置、频道表排序辅助函数的单元测试；`npm run build` 通过；浏览器里走查。

## 7. 明确不做的范围（Out of Scope）

- **目标跟踪**（给频道设目标并追踪）：并入计划 16 的"增长闭环"，和任务、效果追踪一起做。
- 竞赛榜、健康分（计划 13）；账号、博主维度下钻与对比（计划 14）；读者侧留存分析（计划 15）。
- 按部门/领域的权限与报表分发（已确定不做）。
