# 频道竞赛榜 · 设计方案

- 日期：2026-10-05
- 状态：待实施（实施计划见 [频道竞赛榜](../plans/2026-10-05-channel-contest.md)）
- 前置依赖：[频道运营驾驶舱](2026-10-05-channel-cockpit-design.md)（频道指标）已实现。

## 1. 背景与目标

让各个领域频道"相互竞争、发现自己的问题"：用一个可解释的健康分给频道排名，看到名次变化和进步最快的频道。综合频道（五个入口）和领域频道（23 个）**分成两个榜**，分开计分、分开排名。

## 2. 榜单与周期

- **领域榜**：23 个领域频道互相比。**综合榜**：关注、推荐、热点、视频、直播五个入口互相比。
- 周期：**周榜**（周一至周日）和**月榜**（自然月）。对比对象是上一个自然周期。
- 榜单每次实时计算，不建表、不做快照；任何历史周期都能重算。

## 3. 健康分（0–100，榜内相对排名）

每个**指标**先在本榜内按百分位打分：第一名 100，最后一名 0，并列取平均（`(比它小的个数 + 0.5 × (并列个数 − 1)) / (榜内频道数 − 1) × 100`）；没有数据（空值）按 0 处理；**指标值为 0 的频道该项一律记 0 分**（没有数据不能靠并列平均白拿分，演示时发现 13 个没数据的领域频道因为并列各拿了 34.8 分才补的这条）；因此一个指标榜内全部为 0 时所有频道该项记 0；榜里只有一个频道时，有数据记 100、没数据记 0。一个**维度**可以由多个指标组成，维度得分是各指标得分的平均。健康分 = Σ 维度权重 × 维度得分。

| 领域榜维度 | 权重 | 指标 |
|---|---|---|
| 自主分发 | 25% | 自主分发占比、自主入口点击率 |
| 流量 | 20% | PV |
| 互动 | 20% | 互动率 |
| 触达用户 | 20% | UV |
| 内容供给 | 15% | 发帖数 |

| 综合榜维度 | 权重 | 指标 |
|---|---|---|
| 点击率 | 30% | 入口点击率 |
| 曝光 | 25% | 入口曝光 |
| 点击 | 25% | 入口点击 |
| 触达用户 | 10% | 触达 UV |
| 领域覆盖 | 10% | 点击涉及的领域数 |

名次：按健康分（取整到一位小数，也就是页面上显示的分数）从高到低，分数相同则名次相同（"1、2、2、4"），同分的先后按频道编号。权重是代码常量。

## 4. 每行内容

名次、相对上期的名次变化（上期名次 − 本期名次，正数是上升）、健康分及变化、各维度得分与权重、最强项、最弱项。上期整体没有数据时（榜内所有频道上期都没有 PV/点击），名次变化和分数变化为空。

**进步榜**：领域榜里健康分相对上期提升最多的前 5 个（只列提升大于 0 的）。

## 5. 接口

- `GET /api/contest/periods?type=WEEK|MONTH`：可选周期，最新的在前，最多 52 个；每项带起止日期和是否已结束（以 PV 数据的最后一天为"现在"）。
- `GET /api/contest/boards?type=&periodStart=`：返回两个榜（领域、综合）和进步榜。`periodStart` 必须是周期起点（周一或每月 1 号），否则 400；`type` 非法 400；没有 PV 数据时周期列表为空。

## 6. 页面

"频道竞赛榜"（`/contest`）：顶部选周榜/月榜和具体周期（默认最近一个已结束的周期）；两个标签页——领域榜、综合榜；前三名卡片、完整榜单（名次变化箭头、健康分、各维度得分条、最强/最弱）；领域榜旁边是进步榜；点一行进入频道详情。

## 7. 测试

- 纯函数：`ContestScorer`（百分位、并列、全零、空值、单频道、多指标维度、加权、同分同名次）。
- 服务：`ContestServiceTest`（周期推算、上期对比、名次变化、进步榜、上期无数据）。
- 集成：`ContestControllerIT`（形状、参数校验）、`ContestEndToEndIT`（回填后两个榜的频道数、分数范围、名次连续性）。
- 前端：展示辅助函数的单元测试；`npm run build`；浏览器走查。

- 按账号、博主的竞赛榜（计划 14 的下钻与对比）。
