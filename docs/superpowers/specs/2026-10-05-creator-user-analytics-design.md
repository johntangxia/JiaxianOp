# 创作者分析与站内用户分析 · 设计方案

- 日期：2026-10-05
- 状态：待实施（实施计划见 [创作者与用户分析](../plans/2026-10-05-creator-user-analytics.md)）
- 前置依赖：路线图 10–16 全部已实现（行为数据、读者分析、下钻、KOL、增长闭环）。

## 1. 目标

两件事，都以"人"为中心，且都不改现有页面：

1. **创作者分析**：回答"创作者有多少、新来的留不留得住、谁表现好、产出是否过度集中、读者是怎么一步步变成创作者的"。
2. **站内用户分析（全员）**：回答"用户处在生命周期的哪一段、谁在流失或回流、谁有价值、他们关心哪些领域"，并能打开**任意一个员工**的完整画像（用户 360）。

## 2. 统一口径

- 统计日 `asOf`：默认取最近一次登录/发帖的日期（同 KOL、读者分析、增长闭环），可显式传。
- **活跃**：当天有任何行为记录（`active_action_log`，同读者分析）。
- **创作者**：窗口内至少发过一次帖（`POST` 行为）的员工。合著内容每位作者都算一次发帖，指标沿用下钻的"作者归属、合著重复计数"约定。
- **互动**：点赞、评论、转发、收藏。**成员**：`asOf` 当天已加入社区的员工。

## 3. 创作者分析（页面 `/creators`，四个标签页）

### 3.1 总览 `GET /api/creators/overview?from&to&granularity`
- 每个周期（DAY/WEEK/MONTH，默认 MONTH）：活跃创作者数（周期内发过帖的去重人数）、**新增创作者**（历史上第一次发帖落在该周期）、发帖数、人均发帖数。
- 汇总（窗口 `[from, to]` 对比上一个等长窗口）：创作者数、新增创作者、**流失创作者**（上期发过帖、本期没发）、**回流创作者**（本期发帖、上期没发、但更早发过）、创作者占成员比、发帖总数。
- **创作者留存同期群**：按"首次发帖月"分组，第 k 列 = 之后第 k 个月里至少又发过一次帖的人占比；数据未覆盖的月为空；区间内首次发帖的创作者才进同期群；`periods` 默认 6，最多 12。

### 3.2 排行 `GET /api/creators/ranking?from&to&sort&dept&limit&offset`
窗口内的创作者列表，每人：姓名、部门、发帖数、PV、UV、互动数、互动率、平均读完率、名下账号新增关注者（成员所在账号的新增关注，团队账号共享时每位成员都计完整数，页面注明）。`sort` ∈ POSTS / PV / INTERACTION_RATE / COMPLETION / NEW_FOLLOWERS，默认 PV，从大到小，缺失值排最后；`dept` 可选；`limit` 1–100（默认 20）、`offset` ≥ 0；返回总数和部门列表。姓名可点进博主下钻页。

### 3.3 成长阶梯 `GET /api/creators/ladder?asOf`
按**截至 asOf 的累计行为**给每个成员定一个阶段（只取最高的一个）：

| 阶段 | 定义 |
|---|---|
| 未激活 | 从未有过任何行为 |
| 读者 | 有行为，从未互动也从未发过帖 |
| 互动者 | 互动过，从未发过帖 |
| 创作者 | 发过帖，但近 90 天发帖少于 3 篇 |
| 活跃创作者 | 近 90 天发帖 ≥ 3 篇 |
| KOL | 最近一次不晚于 asOf 的 KOL 重算里被判为明星 KOL |

返回各阶段人数和占比；以及**到达率和耗时**：到达"首次浏览/首次互动/首次发帖"的成员占比，以及从加入社区到那一步的中位天数（只统计到达了的人）。

### 3.4 集中度 `GET /api/creators/concentration?from&to`
- 窗口内创作者按 PV 从高到低：前 1 名、前 5 名、前 10%、前 20% 创作者贡献的 PV 占比和发帖占比；**基尼系数**（0 = 完全均匀，1 = 全部集中在一人）。
- **个人账号 vs 团队账号**：各自的创作者数、发帖数、PV、互动数、互动率。

## 4. 站内用户分析（页面 `/users` 和 `/users/:id`）

### 4.1 生命周期 `GET /api/users/lifecycle?asOf`
窗口 W = `[asOf−29, asOf]`，P = 前一个 30 天。每个成员属于且只属于一个阶段（按顺序判断）：

| 阶段 | 定义 |
|---|---|
| 新成员 | 加入日期在 W 内 |
| 活跃 | W 和 P 都有行为 |
| 回流 | W 有行为、P 没有，但更早（P 之前）有过行为 |
| 沉默 | W 没有行为，P 有 |
| 流失 | W、P 都没有，但更早有过行为 |
| 未激活 | 加入早于 W，且从来没有任何行为 |

W 有行为、P 没有、更早也没有（加入早于 W 但第一次行为在 W 里）的归入"回流"（首次被激活）。返回当前各阶段人数和占比、上一个时点（asOf−30）各阶段人数，以及**流转矩阵**（上一个时点的阶段 → 现在的阶段，上个时点还不是成员的算"此前非成员"）。

### 4.2 价值分层 `GET /api/users/value?asOf`
对全体成员按近 90 天打 RFM（1–5 分，榜内百分位，没有数据得 1 分）：R = 距最近一次行为的天数（越近越高）；F = 活跃天数；M = 参与分 = 浏览数 + 3 × 互动数 + 10 × 发帖数。分层（按顺序）：

| 分层 | 定义 |
|---|---|
| 核心 | M ≥ 4 且 R ≥ 4 |
| 活跃 | M ≥ 3 且 R ≥ 3 |
| 待唤醒 | R ≤ 2 且（F ≥ 3 或 M ≥ 3）——曾经有价值、现在沉下去了 |
| 低活跃 | R ≥ 3 且 M ≤ 2 |
| 沉睡 | 其余 |

返回各分层人数和占比，以及每层的人均参与分、人均活跃天数。（这是对 KOL 的 RFM 的补充：KOL 只看积分前 1000 名，这里覆盖全员并用浏览/互动/发帖打分。）

### 4.3 兴趣与跨领域 `GET /api/users/interests?asOf&days=90`
按部门（部门 = 领域）统计成员近 `days`（7–180，默认 90）天的浏览：**本领域阅读占比**（浏览的内容属于自己所在领域的占比）、浏览总数、读者人数、阅读最多的前 3 个**其他领域**及占比。用来看哪些领域封闭、哪些领域的人爱看别的领域、领域之间谁在吸引谁。

### 4.4 用户列表 `GET /api/users/list?asOf&stage&value&dept&q&sort&limit&offset`
全体成员，每人：姓名、部门、加入日期、生命周期阶段、价值分层、最近活跃日、近 90 天活跃天数、浏览/互动/发帖数。可按阶段、价值分层、部门、姓名（包含匹配）筛选；`sort` ∈ LAST_ACTIVE（默认，最近的在前）/ VIEWS / INTERACTIONS / POSTS / ACTIVE_DAYS，从大到小；`limit` 1–100（默认 20）、`offset` ≥ 0；返回总数和部门列表。

### 4.5 用户 360 `GET /api/users/{id}?asOf`
- **基本信息**：姓名、部门、加入日期、在社区的天数、生命周期阶段（现在和上一个时点）、价值分层、是否在 KOL 名单里、KOL 分层和名次。
- **近 30 天**：活跃天数、最近活跃日、浏览/互动/发帖数、角色（同读者分析）。
- **活跃时间轴**：最近 12 周，每周的登录/浏览/互动/发帖次数。
- **阅读偏好**（近 90 天）：看得最多的领域（前 6，含占比）、最常见的标签（前 8）、来源构成（入口/搜索/分享/其他）、视频 vs 文章、平均停留和读完率。
- **关注的账号**：账号名、关注时间、是否仍在关注。
- **积分**：近 12 个月主动/被动积分合计。
- **最近 20 条行为**。
- 员工不存在 404；有发帖时给出博主下钻页入口，在 KOL 名单里时给出 KOL 详情入口。

## 5. 页面

- `/creators` "创作者分析"：四个标签页（总览、排行、成长阶梯、集中度）。默认区间是最近 180 天（以最近一次登录/发帖日为终点），沿用读者分析的区间选择和快捷项。
- `/users` "用户分析"：四个标签页（生命周期、价值分层、兴趣与跨领域、用户列表）；用户列表的姓名点进 `/users/:id`。
- `/users/:id` "用户 360"。
- 读者分析的沉默读者名单、增长闭环里的博主告警：姓名链接改为指向用户 360（比博主页信息全）。

## 6. 后端结构

新增 `people` 包：纯函数（`CreatorMetrics`/`CreatorStageClassifier`/`LifecycleClassifier`/`ValueSegmenter`/`GiniCalculator`/中位数等）、`PeopleQueryRepository`（只加这几份新查询，其余复用 `ReaderQueryRepository`、`SubjectQueryRepository`）、`CreatorService`、`UserService`、两个控制器和异常处理。

**计算量说明**：用户列表、生命周期、价值分层都要扫描全体成员近 90 天的 (员工, 日) 活跃记录，请求内现算、不缓存；演示规模（1000 人）下每次约一两秒，更大规模需要预计算（不在本计划内）。

## 7. 测试
纯函数（阶段判定、生命周期流转、RFM 分层、基尼、中位数、留存）、仓库（2019 夹具）、服务与接口（校验、形状、排序分页）、端到端（回填后：生命周期各阶段之和 = 成员数、流转矩阵行和 = 上个时点成员数、价值分层之和 = 成员数、创作者排行里每人 posts > 0、用户 360 的阶段和列表里的一致）、前端工具函数和图表配置、浏览器走查。

## 8. 明确不做的范围（Out of Scope）
- 预计算和缓存、推荐算法（"推荐关注谁"）、个体级别的预测（流失概率）。
- 创作者激励发放、用户分组导出、用户之间的关注图（关注的是账号，不是人）。
- 修改已有页面（只改读者分析沉默读者名单和增长闭环里的姓名链接目标）。
