# 下钻与对比 · 设计方案

- 日期：2026-10-05
- 状态：已实现（实施计划见 [下钻与对比](../plans/2026-10-05-drilldown-compare.md)）
- 前置依赖：[频道运营驾驶舱](2026-10-05-channel-cockpit-design.md)（频道指标、详情页）和[行为数据扩充](2026-10-05-behavior-data-design.md)（来源、曝光、停留、关注）已实现。

## 1. 目标

分析维度要支持频道、账号、博主个人，并能逐级下钻：**频道 → 账号 → 博主 → 内容**，每一级用和频道驾驶舱一致的指标口径；再加一个对比页，把 2–5 个同类对象并排看。

## 2. 对象与指标口径

四类对象共用一套"内容侧"指标（内容属于该对象，不论从哪里被看到）：

| 对象 | 归属规则 |
|---|---|
| 频道 | 内容所属频道（只有领域频道有内容） |
| 账号 | 内容所属账号 |
| 博主 | 内容的作者（`content_author`）；**合著内容每位作者都记完整的 PV 和互动**，与现有 PV 分析的约定一致，页面上注明 |
| 内容 | 单篇内容 |

指标（`SubjectMetrics`）：
- 内容侧（`ContentMetrics`，同驾驶舱）：PV、UV、互动数、互动率、头部集中度（单篇/前三篇占比）、来源构成（自主入口/综合入口/搜索/分享/其他）、自主分发占比、综合依赖度。
- 供给（`SupplyMetrics`）：期间发布的内容数和去重作者数。
- 内容曝光（`ExposureMetrics`）：这些内容在**各入口**获得的曝光、点击、点击率，平均停留，读完/播完率。（注意与驾驶舱不同：驾驶舱的曝光是"某个频道入口展示了什么"，这里是"这些内容被展示了多少"。）
- 关注者（`FollowerMetrics`，只有账号有）：期末仍在关注的人数、期间新增、期间取关。

每个指标同时给出上一个等长周期的值。

## 3. 下钻页面与接口

| 层级 | 页面 | 接口 | 内容 |
|---|---|---|---|
| 频道 | 已有的 `/channels/:id` | `GET /api/drill/channels/{id}/accounts?from&to` | 新增"该频道下的账号"表：内容数、PV、UV、互动率、自主分发占比、关注者数与新增；点一行进账号 |
| 账号 | `/accounts/:id` | `GET /api/drill/accounts/{id}?from&to&granularity` | KPI、PV 来源趋势（含新增/取关）、来源构成、各作者、各频道分布、Top 内容 |
| 博主 | `/bloggers/:id` | `GET /api/drill/bloggers/{id}?...` | 作为作者的 KPI、趋势、构成、所属账号、各频道分布、Top 内容；已在 KOL 名单里的博主给出 KOL 详情入口 |
| 内容 | `/contents/:id` | `GET /api/drill/contents/{id}?...` | 单篇内容：日趋势、来源构成、各入口曝光与点击率、停留与读完率、互动与评论数、标签、作者、账号、频道 |

- 所有页面带面包屑（频道 › 账号 › 博主 › 内容），范围（from、to）通过路由 query 一路传递。
- 综合频道详情里"点击内容所属领域"的每一块可点进该领域频道。
- `granularity` 取 DAY/WEEK/MONTH，默认 DAY；趋势按周期补零。
- 日期范围最长 366 天，两端含；`to` 不能早于 `from`；对象不存在 404；参数非法 400 + 一句文字说明。
- 博主这一层只看"作为作者"的表现；作为读者的行为（留存、沉默读者）在计划 15。

## 4. 对比

- `GET /api/compare?type=CHANNEL|ACCOUNT|BLOGGER&ids=1,2,3&from&to&granularity`：2–5 个同类对象，id 不能重复；频道只能是领域频道（综合频道没有内容，400）。返回每个对象的名称、当期/上期指标、趋势；频道额外带自己入口的分发（同驾驶舱的 `DistributionMetrics`）。
- 页面 `/compare`：选类型，用已有的远程搜索选择器选账号/博主（频道用下拉），选周期；**指标对照表**（每行标出最优项，指标越大越好或越小越好有明确规则）、**PV 趋势叠加折线**、**来源构成堆叠柱**。

## 5. 后端结构

新增 `drill` 包：`SubjectType`（频道/账号/博主/内容各自的分组列和是否需要作者连接）→ `SubjectQueryRepository`（按分组键参数化的聚合查询，支持按频道/账号/作者/对象 id 过滤）→ `DrillService`（装配指标、趋势、构成、Top 内容、对比）→ `DrillController`（+ 异常处理）。内容侧指标的计算抽成 `ContentMetricsFactory`，驾驶舱和下钻共用。

## 5.1 实现时的偏差

- 前端类型叫 `DrillAccountInfo`、`DrillPerson`、`DrillBloggerInfo`、`DrillContentInfo`，避免和已有的 `AccountOption`、`EmployeeOption` 一类同名接口混淆（上一个计划里 `PeriodOption` 同名被 TypeScript 合并过一次）。
- `BaseChart` 新增 `chartClick` 事件，综合频道详情里"点击内容所属领域"的饼图据此可点。
- 对比页的"添加对象"用单选控件加已选标签（远程搜索选择器本身是单选），标签上的名字来自搜索结果或对比接口的返回，从链接直接打开时先显示 `#id` 再换成名字。
- 对比页的指标对照表里，全部对象的值相同时不标"最优"；PV、UV 额外显示相对上期的变化。
- 账号、博主页的"所属账号/各频道分布"只列当期有数据的对象；"该频道下的账号"和"作者"列出全部（含当期没有数据的），因为它们是下钻的入口。
- KOL 详情的入口只在博主已在 KOL 名单里（`blogger_rfm_score` 有记录）时显示。
- 冒烟测试新增 7 项下钻/对比检查。
- 已知局限：下钻页没有诊断规则；博主按作者归属，合著内容重复计数，所以账号下各作者的 PV 之和可能大于账号合计（页面上已注明）。

## 6. 测试

- 纯函数：`ContentMetricsFactory`、对比最优项判断。
- 仓库：2019 年夹具（两个账号、合著内容、多频道、关注/取关）逐项核对。
- 服务与接口：装配、补零、校验（范围、重复 id、综合频道、不存在对象）、形状。
- 端到端：回填后账号 PV 之和 = 频道 PV；博主维度合著计重；内容页的入口点击和等于来源为入口的 PV。
- 前端：工具函数和图表配置的单元测试；`npm run build`；浏览器走查整条下钻路径和对比页。

## 7. 明确不做的范围（Out of Scope）

- 博主作为读者的分析（计划 15）。
- 账号、博主的诊断规则和竞赛榜；内容的管理操作（编辑、下线）。
- 混合类型对比；超过 5 个对象的对比。
